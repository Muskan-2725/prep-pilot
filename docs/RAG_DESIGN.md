# RAG design
Current implementation uses a tiny curated knowledge pack and an official-source record, not vector search; this is intentional and disclosed in the UI/API. Future RAG stores resource metadata and chunks in PostgreSQL + pgvector; chunk by semantic headings (about 400–700 tokens with overlap), embed versioned chunks, use cosine similarity plus source-quality/freshness filters, return source URLs, and abstain below a threshold. Re-crawl date-sensitive sources; flag stale chunks. Evaluate retrieval with a labelled GATE query set using recall@k and source-quality rate separately from answer quality. Treat retrieved text as untrusted input and never execute its instructions.
